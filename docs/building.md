# Building and testing

## What you need

- CMake 3.24 or newer and Ninja
- A C++20 compiler: GCC 11+, Clang 14+ or Visual Studio 2022
- Qt 6.5 or newer (CI uses 6.8 LTS) with the modules Qt Quick, Qt Multimedia and Qt PDF, and Qt's private Gui headers (included in the official Qt installers)
- Linux only: the ALSA headers (for MIDI)

## Linux

### Fedora (as the project is developed: in a toolbox container)

```sh
toolbox create lumen
toolbox run -c lumen sudo dnf install -y cmake ninja-build gcc-c++ \
    qt6-qtbase-devel qt6-qtbase-private-devel qt6-qtdeclarative-devel qt6-qtmultimedia-devel \
    qt6-qtpdf-devel alsa-lib-devel mesa-libGL-devel
toolbox run -c lumen cmake --preset debug
toolbox run -c lumen cmake --build --preset debug
```

Optional, for the tests that use them: `strace` (offline check), `libreoffice-impress` (PowerPoint conversion test).

### Ubuntu and Debian

Install Qt 6.8 with the Qt online installer or [aqtinstall](https://github.com/miurahr/aqtinstall) (modules `qtmultimedia qtpdf`), then:

```sh
sudo apt-get install -y cmake ninja-build g++ libgl1-mesa-dev libegl1-mesa-dev libxkbcommon-dev \
    libfontconfig1-dev libasound2-dev libpulse0 libva2 libva-drm2 libva-x11-2
cmake --preset debug -DCMAKE_PREFIX_PATH=$HOME/Qt/6.8.3/gcc_64
cmake --build --preset debug
```

## Windows

1. Install Visual Studio 2022 (Desktop development with C++), CMake and Ninja (both come with Visual Studio).
2. Install Qt 6.8 for MSVC 2022 64-bit with the online installer, with Qt Multimedia and Qt PDF.
3. In a *x64 Native Tools Command Prompt*:

```bat
cmake --preset debug -DCMAKE_PREFIX_PATH=C:\Qt\6.8.3\msvc2022_64
cmake --build --preset debug
ctest --preset debug
```

The Windows build has only been built by CI, not tried on a Windows PC yet: reports and fixes are very welcome.

## macOS

1. Install Xcode's command line tools, CMake and Ninja (`brew install cmake ninja`).
2. Install Qt 6.8 for macOS with the online installer, with Qt Multimedia and Qt PDF.

```sh
cmake --preset debug -DCMAKE_PREFIX_PATH=$HOME/Qt/6.8.3/macos
cmake --build --preset debug
```

The app is `build/debug/bin/Lumen Presenter.app`. As on Windows, macOS has only been built by CI so far.

## Running

```sh
./build/debug/bin/lumen                     # your library (in the app's data folder)
```

Useful options: `--no-output` (no audience output), `--output` (start the output even when it was turned off), `--render-option=--screen=1` (the output's screen), `--render-option=--windowed`. `lumen --help` lists them all. `lumen-render --help` lists the renderer's.

## Tests

```sh
ctest --preset debug                 # everything, offscreen
ctest --preset debug -R tst_editor   # one test
./build/debug/bin/tst_editor         # a test program directly (set QT_QPA_PLATFORM=offscreen
                                     # and QT_QUICK_BACKEND=software to match CTest)
```

Every test runs offscreen; no display is needed. A few look for things on the machine and skip themselves without them: LibreOffice (PowerPoint conversion), strace and network namespaces (offline checks), an audio device (timecode with real audio), a MIDI system (virtual MIDI controller), multicast (finding computers).

Long runs, for the requirements that need them:

| What | How |
| --- | --- |
| A 2-hour video loop with no dropped frames | `LUMEN_SOAK_SECONDS=7200 LUMEN_REQUIRE_HW=1 build/release/bin/tst_video_soak` (with sleep blocked: `systemd-inhibit --what=sleep:idle ...`; `LUMEN_SOAK_SCREEN=1` plays fullscreen on screen 1) |
| An hour-long scripted service with no output failures | `LUMEN_REHEARSAL_SECONDS=3600 build/release/bin/tst_rehearsal` |

Some tests can save pictures to look at: `LUMEN_SCREENSHOT_DIR` (main window, theme editor), `LUMEN_EDITOR_DUMP`, `LUMEN_STAGE_DUMP`, `LUMEN_PROPS_DUMP`, `LUMEN_STREAM_DUMP`, `LUMEN_DECK_DUMP`.

Test data is generated by scripts beside it, so it can be remade and extended: `tests/data/decks/make_decks.py`, `tests/data/libraries/make_libraries.py`.

## Packaging

Windows `.msi`, macOS `.dmg`, Linux AppImage, Flatpak, `.deb` and `.rpm`: see [packaging/README.md](../packaging/README.md). `lumen --check-install` checks an installed copy works.

## Continuous integration

`.github/workflows/ci.yml` builds the release preset and runs every test on Ubuntu 24.04, macOS 15 and Windows 2022 with Qt 6.8.3, and builds the AppImage on Ubuntu 22.04. `.github/workflows/packages.yml` builds and checks every installer.
